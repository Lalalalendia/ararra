# РидЭра — перенос UI на Jinja2 / books_platform

**Решение владельца (2026-10-17):** использовать существующие HTML/CSS/JavaScript
из \`books_platform\`, а не повторно писать интерфейс на React. Translation Core,
SQLite API, ID книг/глав, очередь, проверка ревизий, права команды остаются в
\`ararra\` без замены.

## Статус и границы

Этот пакет добавляет рабочий **FastAPI-served Jinja2 + vanilla JS** интерфейс
под \`/app\` и ресурсы под \`/app-static\`. Старый React/Vite оставлен только
как **контрольная реализация на время приёмки паритета**; он не назначен
обязательным для работы нового интерфейса. Production VPN/HTTPS и админский
bootstrap по-прежнему блокированы отдельным деплоем, а не фронтенд-кодом.

Jinja2 рендерит страницу, общую навигацию и формы на сервере. Данные книг,
импорта и участников запрашиваются браузерным модулем \`readera.mjs\` через
защищённые **существующие API /v1/** с \`X-API-Key\`. После входа ключ остаётся
только в памяти вкладки: нет нового cookie/session backend, localStorage,
sessionStorage, URL-параметров с секретами или права для анонимов получать
внутренние книги. После перезагрузки/перехода вне интерфейса ключ вводится
заново. HTML без ключа содержит только статическую форму входа.

**Аутентификация:** ровно две глобальные роли admin/moderator. Ответственный
модератор книги — учётные метаданные, не ACL и не третья роль. Единственный
admin ID задаётся на хосте, без автоматического назначения или HTTP-эскалации.

## Копирование и адаптация конкретных источников

| Оригинал из загруженного \`books_platform\` | Что перенесено в \`ararra\` | Тип |
|---|---|---|
| \`backend/app/web/static/css/components/chapter-import.css\` | \`src/chaptera_server/web_ui/static/css/books-platform-chapter-import.css\` | **Дословная CSS-копия** с добавленным заголовком происхождения |
| \`backend/app/web/templates/books/import_chapters.html\` | \`src/chaptera_server/web_ui/templates/shell.html\` | **Адаптация структуры**: \`chapter-import-upload\`, секции файла, пояснения, действия, история загрузок |
| \`backend/app/web/static/js/chapter-import-status.js\` | \`src/chaptera_server/web_ui/static/js/readera.mjs\` | **Переиспользование идеи DOM-status и исходных классов**, без несовместимого cookie polling: новые API используют командные ключи и атомарный stage |
| \`backend/app/web/routes/books_chapter_import.py\` | \`src/chaptera_server/http/routers/ui.py\` + существующие \`http/routers/imports.py\` | **Не копировать backend напрямую:** зависим от старого пользователя, YDB, монетизации и очереди импорта |
| \`backend/app/web/templates/books/chapter_form.html\` | **Отложено до RE-04** — отдельный редактор глав и переводов | Базу форм можно адаптировать позже, но платные главы, публикация и сценовый редактор не нужны |
| \`backend/app/web/static/js/chapter-import-form.js\` | **Не переносить:** переключает поля платных глав | Не соответствует техническому сайту |

В \`readera.css\` определены CSS custom properties исходной темы и отдельно
оформлены общий shell, таблицы и адаптивная навигация. Оригинальные CSS
классы не заменены произвольными UI-фреймворками.

## Реальные страницы

- \`/app/overview\`: стартовая панель, фактические числа книг и заданий.
- \`/app/books\`: общая библиотека из \`GET /v1/books\`, фильтрация,
  ответственный модератор и версия назначения.
- \`/app/import\`: исходник TXT/HTML/EPUB/DOCX (до 12 МиБ), actor-owned
  staged import и восстановление по ID (TTL 30 минут), предпросмотр/предисловие,
  сопоставление *каждой* главы create/replace/skip, назначение книги и
  модератора, чтение живой версии существующей главы перед replace,
  подтверждение всей партии одним CAS-транзакционным POST. Успех показывает
  квитанцию. \`DELETE /v1/imports/stages/{id}\` явно освобождает слот
  после подтверждения пользователя. Дополнительных платных Gemini вызовов нет.
- \`/app/team\`: admin-only список участников, выдача случайных ключей
  модераторам, одноразовое отображение выданного ключа, перевыпуск,
  отключение с явным подтверждением. Нет просмотра секрета повторно.
- \`/app/jobs\`: текущая очередь и статусы только для просмотра. Кнопка
  «Обновить» не создаёт переводческие задания.

API/проверки принадлежности к actor на сервере остаются авторитетными;
валидация полей в JS повышает удобство, но не разрешает конфликт при
параллельной правке на сервере. JSON Rulate остаётся **метаданными, а не
текстами глав**.

## Инварианты и тесты

- \`tests/test_jinja_ui.py\`: Jinja2 shell 200, закрытые в /v1 данные 401
  без ключа, заголовки \`Cache-Control: private,no-store\`,
  \`Content-Security-Policy\` c запретом inline скриптов, ресурсы после
  packaging, копия CSS присутствует, React не нужен для рендера /app.
- \`src/chaptera_server/web_ui/static/js/import-model.test.mjs\`:
  исполняемые node: отсутствие автоприсвоения для дублирующих/неизвестных
  номеров, skip, безопасные пути, предисловие, revision CAS, TTL.
- Остальной старый HTTP API, \`tools/check_architecture.py\`, Python
  3.11/3.12, React compatibility-check выполняются параллельно.
- **Не пройдено этим PR:** настоящие ручные/Playwright браузерные сценарии
  и пиксельная проверка с Canva, реальный VPS деплой и подключение постоянного
  TLS. Не путать зелёный unit/HTTP CI с пользовательской прод-приёмкой.

## Удаление React/Vite — отдельно после acceptance

1. Прогнать весь сценарий в реальном браузере с двумя ролями на
   изолированном тестовом окружении и несколькими TXT/EPUB/DOCX.
2. Проверить вид/адаптивность в сравнении с эталоном Canva.
3. Доказать, что каждый элемент React-панели (books, import, team, jobs)
   работает в Jinja2 и прямые /v1 API остаются совместимыми.
4. **Только после этого** убрать \`web/\` React/Vite вместе с его архитектурными
   обязательствами и npm workflow отдельным PR. Не обрывать ветку до
   подтверждения качества и не менять production Reader.
