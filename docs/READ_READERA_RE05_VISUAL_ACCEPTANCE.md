# РидЭра · RE-05 · инженерная приёмка UI перед выводом React/Vite

Дата: 2026-10-17. Каноническая issue: [#23](https://github.com/Lalalalendia/ararra/issues/23).

**Решение:** условный **GO на удаление неиспользуемого React/Vite** отдельным PR,
при сохранении Jinja2/vanilla-JS, защищённого API, полноценного Chromium и CI.
**НЕ** означает попиксельное совпадение с Canva, пользовательское утверждение
внешнего вида, релиз или развёртывание на VPS.

## Отличия, которые НЕ являются дефектом

1. Canva содержит фиктивные имена авторов, статус «Опубликовано», типовой
   PDF, лимит 200 МБ, счётчики глав и предполагаемые публикационные
   действия. API этих контрактов ещё не предоставляет. Не выводить
   вымышленные данные, не обещать PDF и не имитировать публикацию.
2. Максимальный импорт **12 МиБ**, а не Canva-образец 200 МБ; это проверенное
   ограничение обработчика.
3. Показ конфликтов на этапе сопоставления + атомарный обзор перед записью
   вместо дублирования полноценной таблицы в последнем шаге.
4. Цвета, типографика и геометрия адаптированы под существующую тему
   `books_platform` и разные экраны. Попиксельное совпадение с Canva
   **не заявляется**.
5. Политика ролей — только **администратор** и **модератор**;
   владелец книги — метаданные ответственности, не третья роль.

## Parity gate для удаления React

Старый `web/` содержит отдельные React-страницы `books/import/team/dashboard`.
Сопоставление функций:

| Старый React | Действующий серверный UI |
|---|---|
| Отдельные формы ключей и список книг | Единый вход в `/app`, `/app/books`, `/v1/books` |
| `ImportPage`, `ImportMapping`, `ImportReview` | `/app/import`, `import-model.mjs`, защищённые import stages |
| Административная команда | `/app/team`, две роли, выдача/ротация/отключение ключей |
| `DashboardPage` | `/app/overview` + `/app/jobs` |
| Отсутствует RE-05 редактор | `/app/editor`: durable draft, notes, history |

Публичные старые React-маршруты `/books`, `/import` и т. п.
**не являются текущим FastAPI-веб-интерфейсом**: в продакшен-сервере
действуют `/app/books`, `/app/import` и т. п. Удаление исходников React
не должно менять ни одного REST-endpoint или таблицы SQLite.

## Обязательные условия отдельного retirement PR

- Удалить только неиспользуемый `web/` и зависимости Vite/React; не трогать
  `chaptera_translation_core`, базу, импорт, шифрование и редакционные записи.
- Удалить обязательность `web/` в архитектурном ratchet.
  **Взамен** требовать все Jinja/vanilla UI-ресурсы и проверять отсутствие
  legacy `web/` после миграции (fail-closed), без ослабления серверных инвариантов.
- В GitHub Actions сохранить Python 3.11/3.12, HTTP/security tests,
  Node 22 `node --check` и реальные `node --test` для импортного решения,
  `npm install --prefix tests/browser` и настоящий Chromium.
- Сохранить скриншоты всех четырёх сценариев и проверку отсутствия
  горизонтального переполнения на мобильном.
- После CI на PR head повторить **post-merge** CI; не развёртывать продукт.

**Граница итогового решения:** инженерный GO относится к замене
**дублирующего и не обслуживающего реальный `/app` фронтенда**, а не
к заявлению `100% Canva` или закрытию полной коммерческой приёмки.
Внешняя ручная pixel/UX-утверждённость остаётся отдельной,
при необходимости продуктовой, задачей.

Production gate: постоянный VPS + HTTPS/VPN и bootstrap из
[chaptera-site #46](https://github.com/Lalalalendia/chaptera-site/issues/46)
не открыт. Платный Gemini этим пакетом не запускается.
