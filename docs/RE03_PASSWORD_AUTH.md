# RE-03-AUTH-PASSWORD-02 — парольная авторизация модераторов

## Статус и границы
Код подключается **только к существующим участникам ReadEra**. Состав ролей не меняется: admin и moderator. Владелец книги остаётся учётным полем ответственности, не новой ролью и не ограничением доступа к общей библиотеке. Публичная регистрация, OAuth, YDB, JWT, письма с паролями и платные вызовы Gemini **не добавляются**. Администратор продолжает входить только с защищённым host key.

Это проверяемый этап разработки в `Lalalalendia/ararra`, а не свидетельство установки на VPS.

## End-to-end-процесс
1. Администратор выбирает **активного модератора** в /app/team и выдаёт временный пароль через `POST /v1/admin/members/{member_id}/password`. Старый пароль инвалидируется. В ответе `temporary_password` отображается однократно. Участника нельзя создать таким запросом.
2. Модератор переключает способ входа на «Пароль» и вводит свой member ID и пароль. `POST /v1/session/password` создаёт стандартную revocable SQLite-сессию с `HttpOnly; Secure; SameSite=Strict` cookie.
3. Первый пароль — **только для смены**. До смены сервер запрещает все защищённые `/v1` операции по этой cookie. Разрешены лишь `GET /v1/session`, `POST /v1/session/logout` и `POST /v1/session/password/change`.
4. После смены пароля по `current_password` и `new_password` сервер отзывает все парольные сессии участника; нужно войти заново. Смена доступна и в обычном кабинете модератора с парольной сессией.
5. Перевыпуск пароля, изменение командного ключа, отключение модератора или изменение его статуса автоматически лишают прежнюю парольную сессию валидности. API-токены сохраняют прежний независимый контракт `X-API-Key`.

## Безопасность
- `argon2-cffi`, Argon2id, 19 MiB memory, 2 iterations, 1 lane, не более 4 одновременных Argon2-операций в процессе; перегрузка — 503/Retry-After; соль на каждый хэш. Хэши и только хэши — в SQLite, строки паролей не сохраняются. Лог выдачи/смены не содержит секретов.
- Случайный администраторский временный пароль с криптографическим генератором, смена своего пароля минимум 12 символов и до 256 байт UTF-8, без управляющих символов.
- Привязка парольной сессии к текущей версии Argon2-хэша и текущему действующему digest командного ключа. Старые сессии team key сохраняются после SQLite-миграции добавления `auth_kind`.
- CSRF-защита применяется к изменяющим запросам по cookie; для смены пароля проверяется явно. Plaintext password в URL, localStorage, sessionStorage, Jinja и журнал событий не передаётся.
- SQLite лимит: по ASGI peer 30 попыток за 15 минут / lock после 8 ошибок; по member ID 10 попыток за 15 минут / lock после 6 ошибок. Атомарная проверка обеих границ, сохранение блокировки после перезапуска, ключи таблицы — SHA-256 идентификаторов. Вход с действительным паролем не сбрасывает общий бюджет запросов.

## Приёмочные тесты
- Python 3.11/3.12: админу доступна выдача, модератору недоступна; неизвестный/отключённый участник не принимает пароль; Argon2-hash-only, одноразовая выдача, смена первого пароля, отзыв сессий при сбросе, отключении и ротации team key, перезапуск, миграция старой SQLite-схемы, CSRF, лимиты по IP и member ID.
- Node/Jinja: модульность и запрет browser persistence / прямых обходных fetch, сохранение UI для импорта и экспорта.
- Chromium: реальный password flow без screenshot с секретами, первая принудительная смена, последующий вход, cookie-restore после reload, общий доступ к библиотеке.

## Production gate
Перенос на VPS и защищённый HTTPS ingress — отдельные RE-01/RE-08. Перед открытием извне обязательно проверяется доверенное ASGI client IP при Nginx/uvicorn proxy headers, корректный TLS, Secure cookies, резервы RAM/параллелизм Argon2, межпроцессное отзыв/backup/restore и ограничения внешнего доступа. Нельзя выдавать зелёный CI за production readiness.
