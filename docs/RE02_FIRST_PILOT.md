# RE-02: первый контролируемый сбор (one-shot)

Цель: проверить один выбранный шаг конкретного задания без постоянного
фонового обхода сайтов, без Gemini и без автоматической записи в библиотеку.

## Предварительные условия

- PR с этим режимом прошёл полный CI и принят в `main`; установленная
  версия точно совпадает с проверенным commit SHA.
- Задание создано через двухэтапный редактор оглавления самим
  авторизованным модератором; `source_job_id` известен из ответа API/UI.
- У владельца есть разрешение на сбор выбранного текста. Проверены robots,
  политика сайта, публичный доступ и ограничения TLS/DNS-проверок. Нет
  обхода логина, CAPTCHA, платного доступа или редиректов.
- Сделаны и проверены резервная копия SQLite, возможность восстановления,
  свободное место под WAL и исходные тексты. Постоянный source-worker выключен.
- Для первой попытки использовать один источник и **одну главу**. Не запускать
  другие сборщики для этого же задания до проверки результата.

## Испытание

В окружении с установленной Эридой и настройкой `CHAPTERA_DB_PATH`:

```sh
chaptera-server source-worker --run-once --job-id "$SOURCE_JOB_ID"
```

- Отсутствующий/неканонический UUID отвергается до загрузки настроек.
- SQL-claim ограничен строго этим UUID и использует обычный транзакционный
  lease/fencing. Другие задания нельзя выбрать «на замену», даже если
  нужное ожидает квоты, уже завершено или удерживается другим процессом.
- Одна попытка обрабатывает не более одной записи. Если сайт отложил
  запрос, причина/ready_at сохраняются в SQLite; повторное выполнение
  возможно только после снятия задержки обычными проверками admission.
- Не объявлять успешным весь импорт по одному нулевому коду процесса:
  inspect job checkpoints, completed/failed/partial, manifest SHA,
  count/ordinals и verified source TXT; после этого отдельно подтвердить
  ImportSessions, если чтение действительно разрешено.

## Чего режим не делает

- Не включает systemd-автозапуск, не запускает многопоточный сбор, не
  переносит ни один старый job, не обращается к Gemini/Drive и не
  подтверждает импорт автоматически.
- Не подменяет site allowlist, robots/TLS и реальные acceptance gates #65/#83.
- Не доказывает, что WebNovel/UUKanshu сохраняют ненумерованные служебные
  записи: их классификация остаётся отдельной проверкой #99.

Первая попытка должна иметь протокол: проверенный commit, идентификатор
источника/книги (без ключей), роботы/разрешения, выбранный ordinal, SHA
манифеста, число checkpoint, причина блокировки/успеха, фактическое
состояние backup/restore. Не писать текст глав или секреты в GitHub Actions.
