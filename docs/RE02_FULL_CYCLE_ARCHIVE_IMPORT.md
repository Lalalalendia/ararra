# RE-02 — Full Cycle App source ZIP → Эрида

## Назначение

Настольный `full_cycle_app` остаётся единственным сборщиком сайтов. Эрида
не делает запросов к исходным сайтам и **не ищет заголовки внутри общего TXT**.
Оператор загружает `*.zip` в существующей форме **«Импорт глав»**.

Поддерживается неизменённый формат экспортёра
`full_cycle_app.chapter_exchange`, `version: 1`, `kind: "source"`.
Архив с переводами (`kind: "translation"`) намеренно отклоняется:
это не исходный материал для Gemini.

## Содержимое

```text
История.zip
├── manifest.json
├── README.txt
├── chapters/
│   ├── 000007.txt    # рабочий текст (normalized/edited, если он был)
│   └── 000009.txt
└── original/
    ├── 000007.txt    # точный parser-original
    └── 000009.txt
```

`manifest.json` определяет **ровно**: `chapter_index`,
`chapter_title`, `chapter_url`, `working_file`, `original_file`,
`working_sha256`, `original_sha256`. Два разных заголовка могут
совпадать; заголовок может не содержать номер. Каждый элемент считается
самостоятельной главой только по идентификатору и ссылкам манифеста.
`chapter_index` используется **как позиция назначения**, но не
выдаётся за авторский номер (`detected_number=null`).

Предпросмотр показывает названия, исходный индекс, URL, размер,
контрольные суммы и предупреждения о внутренних пробелах. **Полноту
оглавления всего сайта нельзя доказать из ZIP:** Full Cycle App экспортирует
лишь собранные непустые главы; такой архив не гарантирует отсутствие
недокачанных страниц, поэтому оператор всегда видит отдельное предупреждение.

Если несколько строк manifest.json используют **один и тот же непустой
chapter_url**, импортёр показывает число повторов и ограниченный список
пар исходных позиций. Также предупреждает, если позиции в манифесте идут
не по возрастанию. Это **диагностика для оператора, а не автоматическое
объединение или удаление глав**: у разных частей главы действительно может
быть общий URL. Первые 32 пары хранятся в preview, но общее число повторов
сохраняется полностью; в веб-интерфейсе показываются первые 8 пар.
Повторы и нарушенный порядок видны и на последнем шаге подтверждения.

В операторской форме рядом с оглавлением выводятся проверенный домен/URL,
количество глав, внутренние пробелы позиций и число отличающихся от оригинала
рабочих текстов. Каждая строка показывает URL, исходную позицию и префиксы
SHA-256 обеих копий. На последнем шаге оператор отдельно подтверждает,
что архив может быть неполным. Это дополнительная UI-проверка: API по-прежнему
требует явного решения по каждой главе и не выводит полноту сайта из ZIP.

## Ограничения и защита

- ZIP максимум **24 MiB** на HTTP-входе, суммарный размер распаковки до
  **64 MiB**, до **2000 глав**; промежуточный JSON-stage — до **24 MiB**.
  Для большего объёма архив разбивается на части и каждый импорт
  подтверждается отдельно. Сверхлимитные архивы не записываются в SQLite.
- Вся структура ZIP проверяется **до** записи: CRC при чтении, запрет
  зашифрованных/нестандартных файлов и неизвестных ZIP-кодеков (разрешены
  только DEFLATED и STORED), симлинков, дублированных путей,
  traversal, лишних TXT, некорректного Unicode, превышения размеров,
  разных ссылок на один member, неправильных SHA-256.
- `/v1/imports/preview` — **только чтение**.
  `/v1/imports/stages` — временное actor-owned хранение с TTL, quota
  и Idempotency-Key; ответ не раскрывает полные главы.
- Оператор подтверждает **каждый** элемент: `create/replace/skip`.
  Существующие редакторские правки защищены CAS по source_revision:
  без явного `replace` исходная глава не перезаписывается;
  принятое редактирование не удаляется автоматически.
  Подтверждение выполняется единым `BEGIN IMMEDIATE`: ошибка любой
  главы откатывает всю партию.
- После подтверждения **оригинал и рабочая версия** сохраняются
  отдельно от canonical `book_chapters.source_html` в
  `book_import_exchange_originals` с ключом
  `(book_id, chapter_id, source_revision)`, исходным URL,
  исходной позицией, SHA-256, актором и временем.
  Ранее сохранённую ревизию другой исходной копией перезаписать нельзя.
  Получить контрольную копию можно через авторизованный
  `GET /v1/imports/books/{book_id}/chapters/{chapter_id}/archive-original`
  (опционально `?source_revision=N`).

## Чего не делает импорт

Он **не запускает платный Gemini**, не выгружает файлы в Drive,
не меняет Python/Rust режим сервера и не обращается к исходному сайту.
Перевод запускается отдельным операторским подтверждением, как для
обычного TXT. ChatGPT остаётся редактором в Google Drive.

## Приёмка

`tests/test_full_cycle_archive_import.py` проверяет реальные v1-поля
архива, неоднозначные названия, пропуски номеров, оригинал против
отредактированной рабочей копии, несовпадения SHA, неполные/опасные ZIP,
stage owner isolation, отсутствие записи в preview, полный rollback,
CAS при замене главы, сохранение принятых редакторских версий,
атомарный импорт, чтение raw-копии после рестарта, HTTP-авторизацию.
Без Google OAuth, Gemini и сетевых исходников.

Безопасность ссылок: source_url и chapter_url допускают только HTTP(S) без встроенных учётных данных. Неожиданные управляющие символы и некорректные Unicode surrogate-символы в метаданных отклоняются до создания временной загрузки.
