# RE-03 — один ключ на участника

**Решение от 18.10.2026:** администратор создаёт участника, получает случайный
256-битный ключ, передаёт его безопасным каналом. Модератор открывает HTTPS
кабинет и вставляет ключ один раз. Ключ обменивается на Secure / HttpOnly /
SameSite=Strict browser session cookie. Выход отзывает сессию. Утрата ключа
решается одним действием администратора «Перевыпустить»; старый ключ и
привязанные к нему сессии перестают работать. Роли остаются admin и moderator.

- **Убрано из интерфейса:** пароль модератора, ID+пароль, временные пароли,
  обязательная смена пароля и дополнительная Basic Auth-плашка Nginx.
- Старые SQLite-записи паролей хранятся без удаления для возможного отката.
  Маршруты /v1/session/password, /v1/session/password/change,
  /v1/admin/members/{member_id}/password отсутствуют;
  старые password cookies отвергаются на уровне серверной сессии.
- Обычный API X-API-Key для доверенных клиентов остаётся неизменным. Ни сырой
  ключ, ни session cookie не должны попадать в логи, URL, HTML или localStorage.
- Web получает одного POST /v1/session, CSRF-token и защищённую cookie.

## Публичная граница

chaptera-server serve на 127.0.0.1:8091 доверяет X-Forwarded-For
**только** от локального Nginx peer 127.0.0.1. Nginx обязан *перезаписывать*,
а не дополнять, заголовок с $remote_addr, иначе клиент сможет подделать IP
и обойти SQLite rate-limit. На всех non-loopback bind Uvicorn не доверяет
proxy headers. Nginx лимитирует /v1/session отдельно по реальному IP.
Внешний порт 8091 никогда не открывается.

## Приёмка

1. Python CI: старые парольные маршруты отсутствуют; password-cookie не
   авторизует пользователя; key-cookie и logout работают; старая
   таблица SQLite мигрирует без потерь.
2. Chromium: одно поле входа, оба уровня роли через ключ,
   reload/cookie и ротация/отзыв без browser-secret persistence.
3. На VPS: сначала pin новой версии Ararra, только потом оператор вручную
   заменяет vhost на проверенный key-only Nginx и убеждается в HTTPS 200
   для /app, 401 для GET /v1/jobs без ключа, 201 для успешного key login,
   429 на излишние попытки с реального внешнего IP; Reader health и память
   не деградировали. Не снижать порог MemAvailable >=320MiB для install.
4. Действительные off-host encrypted backups/restore и production QA —
   отдельные барьеры; смена UI их не закрывает.
